# Final submission readiness: 18 November 2026

## Recommendation: **READY FOR GOVERNMENT TECHNICAL REVIEW**
This means ready to be **reviewed**, as an unofficial prototype on demonstration data. It does **not** mean
government-approved, ready for a pilot, or ready for production. The application has no official data, no live
information and no accounts. Its Android app has not been tested on a phone.

The software and the package in `government_submission_2026/` are ready, but four owner actions must happen
**before anything is sent** (checklist 19, section A):
1. Create the 4.0 staging service, or plan an in-person demonstration from a laptop instead.
2. Fill in contact details and signatures.
3. Confirm each addressee by telephone.
4. Decide on a code licence, or keep the wording "publicly available" rather than "open source".

## 5. Is 4.0 publicly deployed?
**No.** `render.yaml` defines a separate 4.0 staging service: branch `v4`, Singapore region, health check
`/api/health`, an admin key generated by Render, and demo data loaded on start. Creating it needs the owner's Render
account. The 3.0 demo stays public at https://bmtc-future-transit-planner-3-0.onrender.com/.
- **Database:** the free plan has no persistent disk, so server-side saved routes are lost on restart. A pilot needs
  PostgreSQL (`DATABASE_URL`) with daily backups.
- **Error logging:** only the hosting provider's own logs; the app keeps no access log by design.

## 6. Does an Android APK exist, and has it been tested?
- **3.0 APK.** The release `app-latest` exists (main, 16 Nov 2026). Its shell blocks telephone and official links,
  including SOS 112, and has no back-button handling. This is fixed on `v4` only; porting the fix to `main` needs
  approval.
- **4.0 APK.** No release exists, and none is published. The compile-only check for this commit was running in GitHub Actions when this was written. It has not been installed or tested on any
  phone.
- **Release guard (new).** A push to `v4` can no longer publish anything. The `app-v4-preview` pre-release needs a
  manual run with "publish_v4_preview" ticked *and* `V4_PLANNER_URL` set. `tests/test_release_guard.py` enforces
  this. `V4_PLANNER_URL` was not set by this work.

## 10. Security and privacy findings
- **No high-severity finding.** Open items:
  - S5, medium: one shared admin key.
  - H1, medium: free hosting has no backups.
  - A1, medium: Android not tested on a phone.
  - S4, low: inline styles allowed by the content security policy.
- **No independent penetration test.**
- **Privacy:** no names, contacts, locations, searches or payment data are stored. Device keys are hashed. "Delete my
  data" was verified end to end. No legal review against the DPDP Act, 2023 has been done.
