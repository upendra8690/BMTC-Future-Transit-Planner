# Security mapping: OWASP ASVS 5.0.0 and OWASP Top 10:2025

This is a partial, self-assessed mapping of the planner to two OWASP documents. It names what the code does, the tests that
check it, and what is not covered. It is not a certification, no OWASP ASVS level is claimed, and no external audit or
penetration test has been done.

- **Targets.** OWASP Application Security Verification Standard 5.0.0, the newest stable release, and the OWASP Top 10:2025.
  Earlier versions (ASVS 4.0.3 and the Top 10:2021) are not the target.
- **Chapters.** The ASVS chapter names below come from the OWASP ASVS index (https://github.com/OWASP/ASVS). The Top 10:2025
  categories come from https://top10.owasp.org/2025/0x00_2025-Introduction/.
- **Evidence.** Test names are in `tests/`. The results of the final run are in [TEST_RESULTS.md](TEST_RESULTS.md).
- **Gaps.** Each chapter lists what is not covered. Read those lists before relying on the mapping.

## OWASP ASVS 5.0.0 by chapter

| Chapter | What the planner does | Evidence | Not covered or open |
|---|---|---|---|
| V1 Encoding and Sanitization | The dashboard escapes text with a helper and sets text with `textContent` where it can. CSV cells that a spreadsheet would read as formulas get a leading apostrophe. PDF text escapes `&`, `<` and `>`. Search text escapes `\`, `%` and `_`. | `test_exports_and_pdf.py` (formula and PDF tests), `test_search.py` (wildcards are literal), `test_text_and_search.py`, `test_dashboard_static.py` (no code built from strings). | The dashboard builds its HTML by string concatenation. Every value must go through the helper. The static tests do not check that every value does. |
| V2 Validation and Business Logic | Pydantic schemas validate request bodies and query parameters. Scenario years are limited to 2027 to 2030. `max_changes` is limited to 2. A search that matches more than 200 stops is cut. A verification needs a non-empty note. | `test_scenarios.py` (validation), `test_api.py` (`test_years_outside_the_supported_range_are_refused`, `test_verifying_a_source_without_evidence_is_refused_and_changes_nothing`), `test_fares.py` (malformed fare files are rejected). | The server does not check what a verification note says. The scenario estimate uses placeholder assumptions, labelled as such. |
| V3 Web Frontend Security | A Content Security Policy with `script-src 'self'`, no `eval`, no inline script and `frame-ancestors 'none'`. No cookies. The administration key is kept in memory only. The browser stores four values. The service worker keeps only public timetable answers, from an allowlist. | `test_security_headers.py` (the full header set on the dashboard), `test_dashboard_static.py` (no inline script or `eval`, storage rules, service worker allowlist and privacy rule). | `style-src` allows `'unsafe-inline'`. The device key, which is a bearer credential, is kept in `localStorage`. |
| V4 API and Web Service | A published OpenAPI document lists 38 operations. Administrative routes are separate. The rate limiter applies to `/api/` paths and returns 429. CORS is off unless `CORS_ORIGINS` is set. | `test_openapi.py` (the upload's 201 and 422 responses are documented), `test_rate_limit.py` (four tests), `test_api.py` (`test_requests_beyond_the_per_minute_limit_get_429`). | No per-user quotas. The API documentation at `/api/docs` is public. |
| V5 File Handling | GTFS uploads are limited by size (`MAX_UPLOAD_MB`), member count, uncompressed size and compression ratio. Path traversal, absolute paths, drive letters, encrypted members and duplicate members are refused. The ZIP is read from memory and never extracted. Uploaded file names are reduced to safe characters. | `test_gtfs_importer.py` (`test_path_traversal_member_rejects_the_feed`, `test_absolute_path_member_rejects_the_feed`, `test_duplicate_member_rejects_the_feed`, `test_suspicious_compression_ratio_is_rejected`, the size and count limits), `test_security.py` (`test_filenames_lose_their_directories_and_unsafe_characters`), `test_importer_regressions.py` (reading stops when the real size is over the limit). | The importer is not a malware scanner. |
| V6 Authentication | The administration key is compared in constant time (`hmac.compare_digest`). With no key configured, administrative routes return 503. A wrong or missing key returns 401. A key shorter than 32 characters is accepted with a warning. | `test_api.py` (`test_admin_routes_are_disabled_when_no_key_is_configured`, `test_admin_requests_need_the_correct_key`), `test_security_headers.py` (`test_a_short_admin_key_is_warned_about_but_still_works`). | One shared administration key. No accounts, no multi-factor authentication, no lockout after failed attempts, and no rotation. |
| V7 Session Management | There are no sessions and no cookies. Each browser holds a device key of 16 to 128 characters, which identifies its scenarios and saved routes. | `test_security.py` (`test_device_key_format_is_enforced`). | The device key does not expire. The only way to revoke it is to clear the browser's storage. |
| V8 Authorization | Administrative routes need the administration key. Scenarios, comparisons, exports and saved routes are scoped to the device key's hash. | `test_api.py` (`test_saved_routes_belong_to_one_device`, `test_scenario_can_be_updated_and_deleted_by_its_owner`, `test_compare_and_exports_are_owner_scoped`). | Two roles only: administrator and device. |
| V9 Self-contained Tokens | Not applicable. The planner issues and accepts no signed tokens. | Not applicable. | Not applicable. |
| V10 OAuth and OIDC | Not applicable. The planner has no OAuth or OpenID Connect login. | Not applicable. | Not applicable. |
| V11 Cryptography | Device keys are stored only as SHA-256 hashes. The administration key is compared in constant time. The browser creates device keys with `crypto.getRandomValues`. TLS is provided by Caddy in the Docker kit. | `test_security.py` (`test_device_keys_are_stored_only_as_sha256`). | The planner does not encrypt the database or its backups. The administration key is stored as configured, not hashed. Caddy's TLS was not run. |
| V12 Secure Communication | The application does not terminate TLS. The Caddy configuration sets HSTS with a 180-day maximum age, and Caddy obtains certificates for `PLANNER_DOMAIN`. The README says that plain HTTP is the default, and that anyone who can read the network traffic can read the keys. | `deploy/Caddyfile` and `docker-compose.yml` were reviewed, and the Compose file was validated with a placeholder domain. | Not run. The Docker image was not built and Caddy was not run. Over plain HTTP the keys are sent unencrypted. |
| V13 Configuration | Administration is closed unless the key is set. Security headers are sent on every response. The Docker kit runs as user `planner` (uid 10001), drops all capabilities and sets `no-new-privileges`. Dependencies are pinned in `requirements-verified.txt`. Configuration with a bad value stops start-up. | `test_security_headers.py`, `test_trusted_proxy.py`, `test_config.py` (`test_defaults_are_safe_when_nothing_is_set`, `test_a_bad_value_stops_start_up_and_names_the_setting`). Dependency audit: see TEST_RESULTS.md. | The container settings were not exercised, because the image was not built. The API documentation is public. |
| V14 Data Protection | Device keys are stored only as hashes. The schema has no field for age or date of birth. The browser keeps four values. The service worker keeps only public timetable answers. The administration key is kept in memory only. | `test_dashboard_static.py` (storage rules and the service worker allowlist), `test_security.py` (hash storage). | Access logs keep query strings, which include searches and coordinates. Backups contain everything. Free-text fields are not checked for personal data. No retention policy is built in. See [PRIVACY.md](PRIVACY.md). |
| V15 Secure Coding and Architecture | Each module has one responsibility. Lint (`ruff`) and static security analysis (`bandit`) run in the final checks. Mutation tests break safety rules in temporary copies, and each broken copy must fail a test. | `tests/mutation/mutation_check.py` and `tests/mutation/planner_mutation_check.py`, with the results in TEST_RESULTS.md. | `bandit` reports no findings for the backend, scripts, migrations, the Android checker, and the browser and mutation harnesses. A separate, informational run over the test modules reports 917 low-severity notes: 912 `assert` uses (B101), two subprocess imports (B404), two subprocess calls (B603) and one use of `random` (B311), all in the top-level test modules. None is medium or high. There is no threat model document. |
| V16 Security Logging and Error Handling | The audit log records the listed actions with an actor, and API actions also record the client address. A failed import is logged with its file name, and the user sees a generic message. The planner's own logs contain no key values. | `test_api.py` (`test_admin_actions_are_written_to_the_audit_log`), `test_cli.py` (`test_new_source_records_the_command_line_as_its_actor`), `test_api.py` (`test_a_backup_that_cannot_be_written_returns_a_reason`). | Saved routes and preferences are not audited. There is no alerting. There are no log retention rules. |
| V17 WebRTC | Not applicable. The planner uses no WebRTC. | Not applicable. | Not applicable. |

## OWASP Top 10:2025

| Category | What the planner does | Open |
|---|---|---|
| A01 Broken Access Control | Administrative routes need the key. Device data is scoped to the device key's hash, with tests for saved routes, scenarios and exports. | One shared administration key. No per-user access. |
| A02 Security Misconfiguration | Security headers on every response. Administration closed without a key. CORS off by default. The Docker kit drops capabilities and runs as a non-root user. | The Docker kit was not built. The API documentation is public. |
| A03 Software Supply Chain Failures | Dependencies are pinned in `requirements-verified.txt`, and `pip-audit` was run against that file and the installed environment. The Leaflet and axe-core licences are shipped with their code. | The base image is pinned by tag, not by digest. No software bill of materials is produced. The release is not signed. |
| A04 Cryptographic Failures | Device keys are stored as SHA-256 hashes. TLS is provided by Caddy in the Docker kit. | Not run. No encryption at rest. The plain-HTTP option on a local network sends keys unencrypted. |
| A05 Injection | Queries use SQLAlchemy with bound values. The raw SQL in `maintenance.py` uses fixed names. Search text is escaped. CSV formulas are neutralised. PDF text is escaped. | None found in the code paths reviewed. |
| A06 Insecure Design | Verified, unverified and estimated data are kept apart. A verification needs evidence. Scenario estimates are labelled as placeholders. Rate limits and upload limits apply. | No threat model document. |
| A07 Authentication Failures | The administration key is compared in constant time. A wrong key returns 401, and no key returns 503. | No lockout, no rotation, no multi-factor authentication. Device keys do not expire. |
| A08 Software or Data Integrity Failures | Each import records a SHA-256. Imports are validated, and rejected feeds store no rows. Migrations run in order at start-up. Backups are verified before they are kept. | Feeds are not signed. Imports are not checked against the publisher's signature. |
| A09 Security Logging & Alerting Failures | An audit log for the listed actions. An access log for requests. Failed imports are logged. | No alerting. Not every change is audited. The access log holds query strings. |
| A10 Mishandling of Exceptional Conditions | A feed that cannot be written is stored as rejected, with a generic message, and its details go to the server log. A backup that cannot be written returns a reason. An unknown data source kind is a validation error, not a server error. | Not tested exhaustively. |

## What this mapping does not claim

- It does not claim an ASVS level, and it does not say that every requirement of a chapter is met.
- It does not replace an assessment of a real deployment. The Docker image, the Caddy configuration and the network setup have
  not been run.
- It does not cover the Android starter, which has not been built.
