# Phase 1 baseline, compatibility matrix and roadmap

Inspection of branch `v4` at commit `a97beae` and of the public service, on 18 November 2026. **No application code was
changed in Phase 1.** Requirements are in [REQUIREMENTS_REGISTER.md](REQUIREMENTS_REGISTER.md); security, privacy and
government requirements are in `government_submission_2026/20_CYBERSECURITY_AND_PRIVACY_CHECKLIST.md`.

## 1. Authorisation baseline
No approval, agreement, API credential, written scope or acceptance criteria from BMTC, BMRCL, DULT or the Government
of Karnataka exists in the project or in the material supplied. Verbal or relayed instructions are not authorisation.
Until written authorisation arrives, the project stays an **independent, unofficial application**, and gated work does
not start. Gates G0 to G6 are in `government_submission_2026/22_APPROVALS_AGREEMENTS_AND_CREDENTIALS.md`.

## 6. Roadmap
### Stage 1: work that needs no permission (proposed; awaits the owner's approval of code changes)
| Priority | Work | Closes |
|---|---|---|
| 1 | Identify visitors reliably behind the hosting proxy; test it on the public service | R1 |
| 2 | Correct the labels: "first train" for Metro; fares and server-saved routes reported truthfully; descriptions without bus claims | D1–D4 |
| 3 | Keep saved routes on the phone while there is no permanent database | D3 |
| 4 | Android wrapper: location on tap, retry screen, downloads, release signing from GitHub secrets, AAB, target API 36, backup off, version code from the build number | A2–A6 |
| 5 | Android tests on the local emulator (a debug build downloaded from CI); a physical phone when available | A1 |
| 6 | Responsive checks at 320 to 430 px and tablet; iPhone safe areas; Firefox; manifest screenshots | K-02, P1, P2 |
| 7 | CI: bandit, pip-audit, browser smoke and axe on each push; Dependabot | C1 |
| 8 | Inline styles moved to the stylesheet; CSP without `'unsafe-inline'` | S4 |
| 9 | Administrator service notices with an official source link and an end date | E-03 |
| 10 | iOS: decide between the PWA (recommended now) and a wrapper built on a macOS CI runner without signing | K-10, K-11 |

### Stage 2: after the owner's decisions (no government permission needed)
- Permanent PostgreSQL database.
- Accounts screens.
- Paid always-on hosting.
- A release-signing key.
- Google Play and Apple accounts.
- A notification channel.
- The OpenCity stops decision and the Pink Line station list.

### Stage 3 onwards: gated by government permission
| Gate | Unlocks |
|---|---|
| G1 data licence | Official BMTC and BMRCL timetables, bus journeys, combined journeys, fares |
| G2 pilot permission and hosting decision | Pilot preparation |
| G3 security clearance and privacy review | Pilot start |
| G4 real-time agreement | Live location, arrival estimates, alerts, freshness indicators |
| G5 ticketing, ONDC and payment agreements | Tickets, passes, QR, payments, refunds, reconciliation |
| G6 the authority's acceptance | Any production or official status |
