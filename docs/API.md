# API reference

The planner exposes a JSON API under `/api`. The running server also publishes an interactive reference:

- Swagger UI: `http://127.0.0.1:8000/api/docs`
- OpenAPI document: `http://127.0.0.1:8000/api/openapi.json`

This page lists every operation (35 in total, as generated by the server) and the rules that apply to all of them.

## Rules that apply everywhere

**Classifications.** Timetable endpoints take a `classification` value of either `OFFICIAL_VERIFIED` or
`UNVERIFIED_FEED`. Each query searches one classification only, so official and unverified data are never mixed in a
result. Future scenarios have their own endpoints and are always `ESTIMATED_SCENARIO`.

**Coverage.** Results only cover dates the stored feed covers. When a year or date has no data, the response says so
in a `message` field. For official data, that message is: "No officially verified timetable is available for this
future year." Nothing is extrapolated.

**Authentication.** Three kinds of caller:

| Caller | Header | Used for |
|---|---|---|
| Anyone | none | Public reads: health, metadata, routes, stops, timetables, journeys, years, data sources |
| A device | `X-Client-Key` (16 to 128 characters, letters, digits, `-` and `_`) | Scenarios, saved routes and preferences belonging to that device. The server keeps only a SHA-256 hash of the key. |
| The administrator | `X-Admin-Key` | Everything under `/api/admin`. Disabled (HTTP 503) unless `ADMIN_API_KEY` is set. |

The dashboard creates a device key in the browser and keeps it in local storage. Clearing site data forgets the key,
and with it access to that device's scenarios.

**Rate limit.** Each client address may make `RATE_LIMIT_PER_MINUTE` requests per minute (120 by default) to `/api/`.
Beyond that the server answers HTTP 429 with `Retry-After: 60`.

**Errors.** Errors use FastAPI's shape, `{"detail": ...}`. The status codes used are:

| Code | Meaning |
|---|---|
| 400 | A required device header is missing or invalid, or an upload is empty |
| 401 | The admin key is missing or wrong |
| 404 | The item does not exist, or belongs to another device |
| 413 | The upload is larger than `MAX_UPLOAD_MB` |
| 422 | A parameter or body failed validation, or an import was rejected (imports return the report in the body) |
| 429 | Rate limit reached |
| 501 | Backup requested for a non-SQLite database |
| 503 | Administration is disabled because `ADMIN_API_KEY` is not set |

## System and years

| Method | Path | Notes |
|---|---|---|
| GET | `/api/health` | Returns `status` and the server time in UTC. |
| GET | `/api/meta` | Planning years (2027 to 2030), the three classifications, the scenario notice and the estimate assumptions. |
| GET | `/api/years/compare` | Coverage of each planning year for both data classifications, and how many scenarios the calling device has in each year. |
| GET | `/api/years/{year}/status` | Coverage for one year (2000 to 2100), with the message for each classification. |

## Timetables (public)

| Method | Path | Parameters | Notes |
|---|---|---|---|
| GET | `/api/routes` | `classification` (default `OFFICIAL_VERIFIED`), `year`, `q` (up to 80 characters), `limit` (1 to 500, default 100) | Searches route short names, long names and GTFS route IDs. `q` is matched literally, so `%` and `_` are not wildcards. |
| GET | `/api/routes/{route_id}` | | Route details: stops for each direction in order, and shapes when the feed has them. |
| GET | `/api/routes/{route_id}/timetable` | `date` (required, `YYYY-MM-DD`) | Trips operating on that date, with a `covered` flag and the coverage dates. |
| GET | `/api/routes/{route_id}/timetable.csv` | `date` (required) | The same timetable as a CSV download. Returns 404 when the date is not covered. |
| GET | `/api/stops` | `classification`, `year`, `q`, `limit` | Searches stop names and GTFS stop IDs. |
| GET | `/api/stops/nearby` | `lat`, `lon` (required), `radius_m` (50 to 5000, default 800), `classification`, `limit` (1 to 200, default 50) | Stops within the radius, nearest first, with `distance_m`. |
| GET | `/api/journey` | `origin`, `destination` (2 to 80 characters each), `date` (required), `classification` | Direct trips only, with no transfers, that call at a matching origin stop before a matching destination stop. |
| GET | `/api/data-sources` | | Public list of data sources, their kind, verification state and classification. |

## Scenarios (device-scoped)

Scenarios are proposed, illustrative services. Every response carries the scenario notice, and the
`estimate` block is built from the placeholder assumptions in `.env` (speed, stop dwell time and road detour factor).

| Method | Path | Notes |
|---|---|---|
| GET | `/api/scenarios` | Optional `year` (2027 to 2030). Without `X-Client-Key` the list is empty and a message asks for the key. |
| POST | `/api/scenarios` | Requires `X-Client-Key`. Returns 201. Body: name (1 to 120 characters), year, route code, origin and destination names with optional coordinates, first and last departure (`HH:MM`), frequency in minutes (1 to 240), operating days (`MON` to `SUN`, one to seven), and up to 30 stops. A warning is returned if the route code matches an official route. |
| GET | `/api/scenarios/compare` | Requires `X-Client-Key`. Query `a` and `b` are scenario IDs. Returns both estimates and their differences. |
| GET | `/api/scenarios/compare.pdf` | The same comparison as a PDF. |
| GET | `/api/scenarios/export.csv` | Your scenarios as CSV, optionally for one year. |
| GET | `/api/scenarios/{scenario_id}` | Requires `X-Client-Key`. Returns 404 for another device's scenario. |
| PUT | `/api/scenarios/{scenario_id}` | Replaces the scenario. Same body as POST. |
| DELETE | `/api/scenarios/{scenario_id}` | Returns 204. |
| GET | `/api/scenarios/{scenario_id}/export.pdf` | One scenario and its estimate as a PDF. |

## Saved routes and preferences (device-scoped)

| Method | Path | Notes |
|---|---|---|
| GET | `/api/saved-routes` | Empty list without `X-Client-Key`. |
| POST | `/api/saved-routes` | Requires `X-Client-Key`. Body: `gtfs_route_id`, `classification` (`OFFICIAL_VERIFIED` or `UNVERIFIED_FEED`) and a label (1 to 200 characters). The route must exist in that classification. Returns 201. |
| DELETE | `/api/saved-routes/{saved_id}` | Returns 204. |
| GET | `/api/preferences` | Empty map without `X-Client-Key`. |
| PUT | `/api/preferences` | Requires `X-Client-Key`. Up to 20 keys. Each key is lowercase letters and underscores (up to 50 characters). Each value is up to 500 characters. |

## Administration (`X-Admin-Key` required)

| Method | Path | Notes |
|---|---|---|
| GET | `/api/admin/data-sources` | Sources with the administrator's note and the name of the person who verified them. |
| POST | `/api/admin/data-sources` | Returns 201. Body: `name`, `publisher`, optional `source_url` (http or https), `license` (default "Not specified"), and `kind` (`OFFICIAL`, `COMMUNITY`, `SYNTHETIC_DEMO` or `UNKNOWN`). A new source is never verified. |
| POST | `/api/admin/data-sources/{source_id}/verify` | Body: `verified` (true or false) and an optional `note` (up to 500 characters). Only a source of kind `OFFICIAL` can be verified. Imports from the source are reclassified in the same step. |
| GET | `/api/admin/imports` | The 200 most recent imports and their reports. |
| POST | `/api/admin/imports` | Multipart form: `file` (a GTFS ZIP) and `data_source_id`. Returns 201 when the import is completed and 422 when it is rejected, in both cases with the report. Returns 413 when the file is over `MAX_UPLOAD_MB`, 400 when it is empty, and 404 when the source does not exist. |
| DELETE | `/api/admin/imports/{import_id}` | Removes an import and its timetable rows. Returns 204. |
| GET | `/api/admin/stats` | Row counts for each table, active imports per classification, and the database type. |
| POST | `/api/admin/backup` | Copies the SQLite database to `BACKUP_DIR`, checks the copy, and returns its file name, size and migration revision. The backup is deleted if the check fails. |
| GET | `/api/admin/audit-logs` | The most recent audit entries (1 to 500, default 100). |

Every administrative change writes an audit entry with the actor and the client address.

## Examples

```bash
# Search official routes. With no official data loaded, this returns an empty list.
curl "http://127.0.0.1:8000/api/routes?classification=OFFICIAL_VERIFIED&year=2027&q=10"

# Timetable of a route (replace ROUTE_ID with an id from a search) on a Monday in 2027
curl "http://127.0.0.1:8000/api/routes/ROUTE_ID/timetable?date=2027-01-11"

# Direct journeys between two stop-name fragments (replace the fragments with names from your feed)
curl "http://127.0.0.1:8000/api/journey?origin=ORIGIN_PART&destination=DESTINATION_PART&date=2027-01-11&classification=UNVERIFIED_FEED"

# Upload a GTFS ZIP as the administrator (replace YOUR_ADMIN_KEY and the source id)
curl -H "X-Admin-Key: YOUR_ADMIN_KEY" -F "data_source_id=1" -F "file=@feed.zip" http://127.0.0.1:8000/api/admin/imports

# Create a scenario for a device
curl -X POST -H "X-Client-Key: my-device-key-0123456789" -H "Content-Type: application/json" \
     -d '{"name":"Trial","year":2028,"route_code":"PROP-1","origin_name":"A","destination_name":"B",
          "first_departure":"06:00","last_departure":"22:00","frequency_minutes":15,
          "operating_days":["MON","TUE","WED","THU","FRI"]}' \
     http://127.0.0.1:8000/api/scenarios
```

The examples use the syntax of bash, zsh and macOS or Linux shells. On Windows, the same requests work with
`curl.exe` in Command Prompt, but the single quotes must become double quotes with the inner quotes escaped. Windows
PowerShell needs its own quoting rules as well.
